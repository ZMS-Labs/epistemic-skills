# epistemic-skills 3.0.0

**Prepared:** 2026-07-26  
**Intended channel:** stable  
**Status:** prepared release record; publication is pending the exact-commit gates, annotated tag, and non-draft GitHub Release

Version 3.0.0 is intended to be the first immutable support point for this repository. It
packages the proportional routine-work path, applying-formal-rigor v2, the
consolidated Gauntlet, and the cross-harness plugin surfaces as one tagged
contract.

This release means that the versioned files, deterministic checks, install
coordinates, release notes, tag, and GitHub Release are intended to agree at one
public commit. It does **not** mean every behavioral question is closed, that
3.0.0 is proven superior in every harness, or that the excluded diagnostic
campaign has been promoted into release evidence.

## Highlights

- A first-class routine-work exit for reversible, local, directly checkable,
  non-precedential work.
- Two-read micro-recon before escalating unfamiliar routine-looking work.
- Silent absent triggers and a narrower Blindspot Pass trigger.
- Decision Ledger reuse of adequate ADRs, plans, issues, PR descriptions, goals,
  and derivations.
- Applying-formal-rigor v2:
  - a genuinely lightweight focused tier capped at six short bullets or 250
    visible words;
  - standard and high-assurance `formal-rigor-record@2` contracts;
  - open-world P1-P9 coverage, applicability proofs, specialist modules,
    source/version rules, and staleness re-fire.
- Evidence-locked UAT proportionality: routine presentation checks cannot emit a
  material UAT PASS packet.
- Gauntlet 3.0 selection with stance anchors, subject-seeded wildcards,
  replayable provenance, exact-role binding, and non-governing telemetry.
- Deterministic proportionality, formal-rigor, UAT, Decision Ledger, package,
  DCO-policy, JSON, receipt, and Gauntlet test coverage.
- Immutable `v3.0.0` install coordinates for supported package surfaces.

## Compatibility and migration

3.0.0 is the first formal release; there is no earlier tagged compatibility
baseline. Existing untagged installs should replace their current copy rather
than layer a second plugin or skills directory over it, then reload the harness
or start a fresh task.

Behavioral changes that integrations must account for:

- routine and absent-trigger paths can be silent;
- focused formal-rigor work is inline and record-free;
- standard/high-assurance formal-rigor work emits
  `formal-rigor-record@2`;
- material Gauntlet runs require isolated role-bound evaluators and an
  independent arbitrator;
- the current Cursor public-marketplace listing is not part of this release;
  use a checkout of tag `v3.0.0` for a stable local Cursor install.

The exact install commands are in
[README.md](../../README.md#install) and are pinned to `v3.0.0`.
