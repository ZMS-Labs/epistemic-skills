## What the candidate establishes

- `watch` is explicitly a commission/proof discipline, not the observer.
- `watch-commission@1` distinguishes current state, complete proof history,
  positive-claim evidence, block evidence, and later observed failure.
- Only an enabled externally persistent mechanism with complete production-path
  proof and a re-proof boundary can be `PROVEN`.
- A successful proof followed by disablement is `INERT` with proof retained.
- A newly prepared mechanism remains `BLOCKED: KILL_SWITCH_UNPROVEN` until its
  real disable path is exercised and receipted.
- `BLOCKED` is evidence-bearing; absence cannot be asserted from memory or lack
  of imagination.
- `SUSPECT` requires an observed, typed, dated, receipted failure.
- Schema and semantic verifier fields/enums are parity-tested.
- Receipt references are mandatory carriers but are not falsely represented as
  authenticated facts.
- Prompt/session/self-asserted evidence and obvious skill-file mechanisms are
  refused; all carried values remain untrusted data.
- Fixture evidence is scoped away from untested production environments.
- The current `watch` skill id remains stable and no alias skill is added.
- Package description cost is reduced to and locked at 8,159 UTF-8 bytes.
- Practical Agency is correctly separated as future mission control with one
