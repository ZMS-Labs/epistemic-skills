## Evidence continuity rules

- Epoch results move with their batteries, never deleted; every moved
  RESULTS.md gains a consolidation note; per EVIDENCE-POLICY rule 1 the
  merged skills' trigger surfaces are new subjects → prior epochs are
  historical evidence and the merged batteries re-arm at Tier 1 (run at the
  v4.0.0 release candidate, Tier 2).
- The `.ledger` store, gauntlet runs, ECS contracts, and all results dirs
  are append-only history — paths inside them are historical citations and
  are NOT rewritten.
- ECS event kinds: recon = {landmine-prediction, frontier-decision,
  harvest-decision}; resolve = {formal-prediction, evidence-claim,
  probe-episode}; decision-ledger = {ledger-revisit, continuity-reanchor}.
  Retired producer names stay in the event schema enums as historical
  values (events are append-only records); the map carries only live
  skills. merge-ruling and interview... (agent-interface/intent-traced
  kinds: consumer-gate-outcome, merge-ruling) retire from the map with
  their skills, remain valid historical enum values.
- Version: this branch is the v4.0.0 arc; the release PR does the tag +
  marketplace version bumps, per house convention.

## Naming decision

`recon` and `resolve` are new names (no dir collision; short; mode-neutral).
`decision-ledger` keeps its name (it is the store's name). Old skill names
remain as mode/instrument names inside the docs so operators' vocabulary
survives ("run a blindspot pass" = recon in brief mode).
