# Using Epistemic Skills

Apply the relevant method before work that depends on it, acknowledge its actual
use, and carry the user's authorized task through to its outcome. This guide
establishes usage rules; the task-owning agent remains responsible for the work.

## Discover, load and apply

1. **Read current discovery descriptions.** Use the host's available skill
   listing and its applicability and exclusion clauses. Honor an explicit skill
   request. Any substantive skill can be used directly; this entry is not an
   extra prerequisite for every invocation.
2. **Load the actual instructions.** Use the host's skill mechanism or read the
   current canonical `SKILL.md`. Load referenced material needed for this case.
   A remembered name, a summary or an announcement does not substitute for the
   method. If instructions or a required capability are unavailable, state that
   limit and use an adequate available alternative without claiming missing use.
3. **Apply the method to the live question.** Reuse relevant evidence and settled
   user decisions. Follow applicable host and user instructions; a skill does
   not create authority, overwrite scope or introduce a universal approval gate.
   Use a substantive method when its conditions arise during work, not only at
   startup. Routine work with no applicable substantive trigger proceeds normally.
4. **Make actual use visible.** Give a brief first-use acknowledgment and a
   concise account of substantive contributions, individually or together.
   For example: "I used Triage with Systematic Debugging to distinguish the
   stale cache from a failed write; the repair now passes the original check."
   A method may confirm an existing approach or return no material finding.
   Do not invent findings to justify use, repeat startup banners, or narrate
   every skill that did not apply.
5. **Continue the task.** Return each bounded result to the work it informs.
   Continue authorized implementation and verification. An assessment-only
   request ends at assessment; a repair request does not end at diagnosis.
   A gap holds only dependent actions or claims. Re-enter a method when new
   evidence or a changed condition warrants it, not to repeat completed work.

Activation discipline: design-argued; no shipped trigger battery as of this change.

## Working with other packages

Prefer available, applicable Superpowers systematic-debugging for debugging.
Load and apply its actual procedure, integrating Triage's causal standards into
one investigation. When unavailable, use the standalone investigation in
Triage's reference. Report the provider actually used. No other package is a
required dependency of this suite. Other methods can likewise cooperate where
their responsibilities are distinct; there are no fixed pairs or mandatory
chains.

## Delivery and identity

The canonical identity is `epistemic`. `using-epistemic-skills` is a compatibility
alias for `epistemic`, not a second implementation. Native alias invocation is
available only where the host adapter has verified support; otherwise use the
canonical name through the host's actual invocation interface.

A supported host may load this body at startup or after context loss. If that
has not been verified, use explicit invocation or load this file. Distinguish
source availability, observed loading and actual application. Do not claim a
startup hook worked merely because its configuration exists. Reuse verified
session knowledge rather than auditing the installation on every turn.

This guide creates no planner, dispatch engine, lens-selection method, verdict,
task ledger or mandatory process artifact. It does not replace substantive
reflection. Its output is usable guidance and a brief acknowledgment; then the
original task continues.
